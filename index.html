VERSION 6.1 · INDEPENDENT COMPATIBILITY PROJECT

CyberBuddy Classic Proxy

Created September 25, 2026 · Version 6.1 release update: October 2, 2026 · Python / Microsoft Windows

Created by Arthur Tube, this Python project restores compatibility with several online services used by the original CyberBuddy client. It is an unofficial preservation project, separate from CyberBuddy's original developer.

Development status · October 5, 2026

The UIN Directory, online presence, persistent UIN data, and Remote Connection Request features are available in 6.1 testing. A new chat patch addresses browser request parsing, message polling, and presence updates. Nine isolated server regression tests passed. Native CyberBuddy Send/Receive still needs a two-client Windows test; Chat remains under development.

Weather, news & email

Current weather and forecasts use Open-Meteo data. News supplies changing headlines in CyberBuddy's format. Email compatibility depends on the account and provider.

Archived Unisys pages contain historical information. Weather alerts depend on location and available sources, including NWS for supported US locations.

Jokes, thoughts & stocks

These three features were completed with the September 30, 2026 version 6.0 update.

Shared UIN Directory

Publish a UIN, display name, and comments in a directory of up to 200 users. Registered entries persist when the proxy restarts and can be used to add CyberBuddy contacts.

Online presence

Clients using the same shared service can appear online to one another. Historical users are kept separate from live presence.

Remote Connection Request

A request includes the requested UIN, CyberBuddy name, comments, request type, and the remote IP obtained from the connection. Request types cover directory publication, Chat, or both. The host can allow, reject, or clear a request.

A TCP connection alone does not publish a UIN: the server must apply the accepted request to its persistent directory.

Why can a UIN appear in the directory but fail in Chat?

The directory, local contact list, and Chat recipient handling are separate parts of the original client. An entry in the shared directory does not confirm that native Chat recognizes the buddy or delivers messages. UIN-to-Chat integration and Send/Receive remain under development.

Published users and online status

Published UIN records survive a proxy restart. Online status depends on recent client activity; saved or archived records do not establish that a buddy is currently connected.

Invite a Buddy

Enter sender and buddy names and email addresses, an optional UIN, and an invitation message. Sending requires a configured email account.

Directory privacy

Public directory information is intended to include display name, UIN, comments, and “Since Last On.” IP addresses are used internally; computer names, Windows usernames, and local paths are not intended as public fields.

BonziBUDDY: a bit of history

BonziBUDDY was a Windows desktop assistant from Bonzi Software, first released in 1999. It initially used Microsoft's Peedy character, then introduced the purple gorilla Bonzi in 2000. Its features included speech, jokes, facts, songs, and desktop tools.

Bonzi, Peedy, Max, and the world of Microsoft Agent are a big part of what I enjoy making and exploring.

Bonzi & Peedy

Character videos, conversations, and classic assistant experiments.

Scripts & voices

Animation, speech, timing, and experiments with Microsoft Agent scripting.

The character, the original program, and my Customizer

Bonzi is a character; the original BonziBUDDY application is separate software with a documented spyware and adware history. Enjoying Microsoft Agent characters does not require installing that original application.

My BonziBuddy Customizer is an independent Python editor for recognized NBD data layouts. It does not include or install the original BonziBUDDY program or databases, and it does not perform network downloads.

The original program's retired servers are not proof that an old installer is safe. For experiments with original software, use an isolated virtual machine.

BonziBuddy Customizer

Created by Arthur Tube. Export recognized .nbd layouts as readable TXT, edit records, validate changes, and apply them with backups. The tool can also restore files and create a new NBD without replacing the installed database.

Download BonziBuddy Customizer
Setup & compatibility

Extract the ZIP to a writable folder, install Python 3.8 or newer, and run START_CUSTOMIZER.bat. Select your BonziBuddy data folder. Close BonziBuddy before applying or restoring files.

Versions 2.0 through 4.1.0.9 are the target range, not a claim that every version has been verified. Unsupported layouts are rejected; playback and the Windows launcher still require testing with BonziBuddy.

Editing & test databases

Normal edit/apply and rebuild actions keep the original record count. TXT import accepts blank lines, reading labels, and code fences, and can restore a missing Header from the original template.

Action 7 creates separate test databases with one or more records, including larger lists. Recognized selection lists can be rebuilt alongside them. Resized databases require Windows playback testing.

Songs retain pitch, speed, and pause commands as text; the tool does not compose melodies or verify musical accuracy.

No original BonziBuddy executable or databases are included. The Customizer itself performs no downloads or network access.

Windows compatibility

The 6.1 installer requires Windows 10 or later, with Windows 10 and Windows 11 listed as supported targets. Older Windows versions are not currently supported by this installer. Future compatibility claims require installation, startup, connection, and feature testing on the specific Windows version.

Before you start

You need your own copy of the original CyberBuddy, Microsoft Windows, Python 3, and an internet connection. The proxy package does not include CyberBuddy.

The 6.1 installer supports Windows 10 and Windows 11, and installs the required components. Earlier Windows releases are not currently supported by this installer.

Start the proxy

  1. Run the Windows installer, or extract the ZIP and follow its included setup instructions.
  2. Start the proxy with START_PROXY.bat.
  3. For local operation, configure CyberBuddy to use 127.0.0.1:8081.
Using more than one client?

All clients must reach the same shared proxy server to use a common UIN directory and presence service. Separate 127.0.0.1 instances do not share their directories. Chat delivery remains under development.

Is chat fully working?

No reliable Chat / Instant Messaging result was confirmed in the October 2 testing. Directory publication and online presence do not guarantee that Chat can recognize a recipient or deliver messages.

What happened to the Archive downloads?

The original Internet Archive item and its replacement became unavailable. Use the GitHub version 6.1 release for the ZIP and installer.
